# Audit issue resolution — 11 October 2026

This checklist maps the external review to checked repository behavior. “Resolved” includes a documented fail-closed result where inputs or a defensible method are not available; it does not mean every metric becomes numeric.

| Review item | Result |
|---|---|
| Per-customer confidence missing | Added a per-recommendation validation-score-band reliability summary with sample size, predicted rate, observed synthetic adoption rate and Wilson 95% interval. The `confidence` field remains null because no individual confidence method is validated; UI/docs explicitly distinguish cohort reliability from personal confidence. |
| Solar unavailable for all customers | London synthetic homeowners with a suitable-roof flag and annual demand now receive a conditional scenario using documented PV yield, representative capacity and archetype self-consumption assumptions. Other coarse regions, missing ownership/roof/demand, and unsupported site yields remain UNAVAILABLE. It is not a customer roof assessment. |
| GHG Protocol / PCAF absent | Added source links and a claims-boundary section. The engine uses baseline-versus-scenario framing only; it is not claimed to conform to the GHG Protocol Project Protocol or calculate PCAF financed emissions. |
| Paperless carbon missing | Kept carbon null. Annual pages avoided are displayed as a documented 48-page scenario, but no verified statement lifecycle factor exists. Inventing a CO₂ factor would be less defensible than explicit unavailability. |
| LLM wording too canned / weak evaluation | Added a standalone prompt/methodology deliverable and expanded offline checks to 28 cases with groundedness, factual accuracy, completeness, numerical consistency, and missing/conflicting-input scores. All score 28/28. These verify exact allow-list behavior, not semantic or live-generation quality. The implementation remains safe sentence selection; no API key/live provider was available to verify free-form generation, so that specific limitation remains. |
| Business trend insight missing | Added `GET /business/trends` and a monthly category spending trend in the business dashboard from the synthetic 2025 transaction records. It is descriptive history, not a forecast. |
| Energy and digital-adoption dashboard metrics | Added synthetic annual electricity-plus-gas demand, paperless adoption share/count, mobile-app activity and mean digital logins/month to business summary and dashboard. Customer-level annual kWh and digital behavior were already present. |
| Excluded products appear as recommendations | Customer view now puts only `POTENTIAL_OPPORTUNITY` entries under green opportunities. Excluded, insufficient-data and review statuses are in a separate collapsed “Not recommended or more information needed” area. |
| Weak propensity baseline | Added four fixed, explainable rule heuristics, evaluated on saved customer splits without fitting or tuning. Results are in `ml/reports/rule_baseline_metrics.json` and compared in the evaluation report. The rules outperform model hard classifications at 0.5 on this cohort; the selected models and existing validation-selected prioritization thresholds are unchanged. |
| Suggested source-schema fields absent | Documented why debit/credit is redundant for an outgoing-spend-only ledger, why postcode is replaced with coarse region, why continuous income replaces a band, why product balances are unused, why vehicle age is not invented, and why energy/digital measurements are annual/prior-month as available. Expanded the catalogue with use cases, required information, exclusions and sustainability metrics. No extra synthetic fields were added to the trained feature contract. |
| Shared merchant templates inflate classifier score | Added a separate merchant-name holdout diagnostic. TF-IDF macro F1 is 0.0946 on 108,289 transactions, versus 0.9209 for the fixed rule baseline. This demonstrates that the 0.9803 customer-held-out score does not generalize to unseen merchant names. The deployed classifier artifact is unchanged. |
| Low transaction-frequency realism | Confirmed: the synthetic ledger produces at most one category-level transaction per active category per month, with random skips for home improvement and automotive. This is disclosed in `docs/synthetic_methodology.md`; the dataset is not a full bank ledger. Replacing it would alter Customer 360, labels, splits and classifier metrics, so it was not silently regenerated during this audit. The merchant-held-out diagnostic makes the current classifier limitation measurable. |
| LCL reading-count proxy may not represent complete days | Current generator provenance and docs say `readings_count // 48` is only a coverage proxy, not complete-day verification. The separate timestamp processor can count valid distinct intervals for future runs; the preserved current synthetic cohort was not regenerated. |
| Duplicate PDF and stray `test.txt` | Removed the byte-identical nested copy and stray tracked text file; the canonical team M1 PDF remains. Corrected README/inventory to call it the team's approach, not the full official brief. |
| Optional innovation | Added a what-if explorer that sends allow-listed hypothetical changes to the backend, reruns the saved propensity pipelines and applies the same screening. It does not persist data. Optional Green Investments/Loans and customer memory remain out of scope. |

## Items that require external evidence or remain intentionally incomplete

- The repository contains only the team's two-page M1 approach document, not the full official Lloyds PS1 PDF. Therefore, statements about exact full-brief clause numbers, scoring weights or an example confidence value cannot be independently confirmed.
- Solar is sourced for a representative London scenario only. A production-quality recommendation requires customer-authorized coordinates, roof/azimuth/shading/site assessment and an up-to-date yield calculation.
- Paperless carbon remains unavailable until statement production, delivery and digital-service lifecycle boundaries and factors are substantiated.
- Live OpenAI generation remains unverified. The safe deterministic fallback works; the optional model only selects approved text and does not create new prose.
- The Low Carbon London license for the exact local distribution still needs confirmation before redistribution. The local raw files are not staged or committed.
